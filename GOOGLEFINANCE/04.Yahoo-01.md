To calculate the average of exactly the first 200 *numeric* values starting from `D352` (skipping any text, blanks, or errors), you can combine the `AVERAGE`, `ARRAY_CONSTRAIN`, and `FILTER` functions.

Here is the formula you should use in cell **D346**:

``` excel
=AVERAGE(ARRAY_CONSTRAIN(FILTER(D352:D, ISNUMBER(D352:D)), 200, 1))

```

### How this works:

2.  **`ARRAY_CONSTRAIN(..., 200, 1)`**: This takes that clean list of numbers and restricts it to exactly the top 200 rows (and 1 column). If there happen to be fewer than 200 numbers available, it will just take whatever is there (which perfectly matches your "up to 200" requirement).
3.  **`AVERAGE(...)`**: Finally, this calculates the average of those specific 200 numeric values.

This is much more robust than `=AVERAGE(D352:D480)` because if you have blank rows or text mixed in, it will dynamically skip them and keep counting downwards until it finds 200 actual numbers.

The formula you are using is a classic example of a deliberate circular reference, 
often used to create a static value (like a timestamp or a "run once and keep" calculation).

The reason it is returning `0` instead of the expected value is likely due to one of two reasons:

**1. Iterative Calculation is Turned Off**
By default, Google Sheets blocks circular references (a cell referring to itself). If Iterative Calculation is not enabled in your settings, the formula cannot resolve the loop, which often results in the cell displaying a `0` or a `#REF!` error.

**2. The Formula "Locked In" a Zero**
If Iterative Calculation *is* turned on, your formula might have temporarily evaluated to `0` when you first entered it (for example, if `GET_CLOSE_PRICE` was still loading or temporarily failed). Because `0` is not equal to an empty string (`""`), the condition `D352<>""` evaluates to `TRUE`. The formula then does exactly what you told it to do: it keeps its current value, permanently locking the cell at `0`.

### How to Fix It

To get the formula working correctly, follow these steps:

**Step 1: Verify Iterative Calculation is ON**

1.  Go to **File** \> **Settings** (or **Spreadsheet settings**).
2.  Click on the **Calculation** tab.
3.  Ensure **Iterative calculation** is set to **On**.
4.  You can leave the default Max iterations at 50 and Threshold at 0.05.

**Step 2: Update the Formula**
To prevent the formula from getting stuck on `0` if the custom function takes a moment to load, you should update your logical check to also look for `0`.

Use this updated formula:

``` 
=IF(OR(D352="", D352=0), GET_CLOSE_PRICE($D$350,C352), D352)
```

**Step 3: Reset the Cell**
Because the cell is currently stuck on `0`, you need to clear its memory.

1.  Delete the formula from cell `D352` and press **Enter** (leaving the cell completely blank).
2.  Paste the updated formula back into `D352`.

This will force the cell to evaluate freshly, fetch the price of 63, and then lock that value in.

```javascript
function onEdit(e) {
  const range = e.range;
  const sheet = range.getSheet();
  
  // 1. Target a specific sheet name (optional, change 'Sheet1' as needed)
  if (sheet.getName() !== 'Sheet1') return;
  
  // 2. Define the target column to watch (e.g., Column 1 = A)
  const targetColumn = 1; 
  
  // 3. Define the column to populate (e.g., Column 2 = B)

  if (range.getColumn() === targetColumn && range.rowStart === range.rowEnd) {
    const row = range.getRow();
    const targetCell = sheet.getRange(row, outputColumn);
    
    // Check if the output cell is ALREADY filled
    if (targetCell.getValue() === "") {
      
      // Calculate or set the value here
      // Example: Setting a static timestamp
      targetCell.setValue(new Date()); 
      
      // Alternative example: Call custom logic or custom functions
      // targetCell.setValue("Your Calculated Value");

  }
```

### How It Works Under the Hood

* **`e` (Event Object):** Contains information about what changed, such as the edited range (`e.range`) and sheet.

# Q09: Iterative Calculations

Is there a way to self-reference a cell in Google Sheet, for example if this 
cell already holds a value do nothing and keep it otherwise determine its value 
calling this function.

Yes, but because Google Sheets normally throws a **Circular Dependency Error** 
when a cell references itself, you must enable **Iterative Calculation** first.

---

### Step 1: Turn on Iterative Calculation

1. Open your Google Sheet.
2. Go to **File > Settings** (or **Spreadsheet settings**).
3. Select the **Calculation** tab.
4. Under **Iterative calculation**, set the toggle to **On**.
5. Set **Max number of iterations** to **1**.
6. Click **Save settings**.

---

### Step 2: Write the Formula

Assuming the formula is placed directly in cell **A1**, 
use `A1` inside its own `IF` statement:

```excel
=IF(A1<>"", A1, YOUR_FUNCTION())

```

* **How it works:** When the cell is empty (`""`), it executes `YOUR_FUNCTION()`. 
Once a value is generated or entered, `A1<>""` evaluates to `TRUE`, so the formula 
returns `A1` (its existing value) and freezes it, preventing further recalculation.

---

### Key Caveat to Keep in Mind

* **Recalculation Behavior:** If you modify `YOUR_FUNCTION()` or clear the cell manually, 
it will recalculate once before locking in again.

* **Alternative (Google Apps Script):** If you want a permanent timestamp or fixed value 
that *never* recalculates even if dependent data updates, an **`onEdit` trigger** in 
Apps Script is generally more reliable than iterative calculation formulas.

No, it is not possible. Iterative calculation is a **spreadsheet-level setting**

### How to Isolate Iterative Formulas Safely

If you need to use iterative formulas (like `=IF(A1<>"", A1, YOUR_FUNCTION())`) 
without affecting the rest of your sheet, use these safeguards:

* **Use Apps Script Instead:** If global iterative calculation causes unintended circular dependency warnings or performance drag in other parts of your sheet, using the `onEdit` Apps Script method remains the best way to restrict self-referencing logic strictly to target cells.

# Q07

Can you generalize `populateHistoricalPrices` so that I can pass the following parameters? 

1. the ticker, 
2. the start date,  
3. the end date, which is later than the start date

# ANSWER 07: Gemini Flash

Here is the generalized version of `populateHistoricalPrices`. 
You can pass a ticker symbol, a start date, and an end date as parameters.

It iterates day-by-day from the start date to the end date, fetches the close price 
using your `GET_CLOSE_PRICE` function, and writes the results as hardcoded static 
values into the active sheet.

### Generalized Apps Script Function

```javascript
/**
 * Populates historical closing prices for a given ticker between two dates
 * and writes the results as static values into the active sheet.
 *
 * @param {string} ticker - The ticker symbol (e.g., "EXSA.DE", "AAPL")
 * @param {string|Date} startDate - Start date (e.g., "2024-01-01" or a Date object)
 * @param {string|Date} endDate - End date (must be equal to or after startDate)
 * @param {number} [startRow=2] - (Optional) The starting row in the sheet to write data. Defaults to 2.
 */
function populateHistoricalPrices(ticker, startDate, endDate, startRow = 2) {
  const start = new Date(startDate);
  const end = new Date(endDate);

  // Validation
  if (!ticker || typeof ticker !== "string") {
    throw new Error("Invalid Ticker.");
  }
  if (isNaN(start.getTime()) || isNaN(end.getTime())) {
    throw new Error("Invalid Start or End Date.");
  }
  if (start > end) {
    throw new Error("Start date must be earlier than or equal to End date.");
  }

  const sheet = SpreadsheetApp.getActiveSpreadsheet().getActiveSheet();
  const rows = [];
  
  // Clone start date to avoid modifying original reference
  let currentDate = new Date(start);

  // Iterate day-by-day until reaching the end date
  while (currentDate <= end) {
    // Format date string as YYYY-MM-DD
    const dateStr = currentDate.toISOString().split('T')[0];
    
    // Call your custom function to fetch/get the price
    const price = GET_CLOSE_PRICE(ticker, currentDate);
    
    // Push a row: [Date, Ticker, Close Price]
    rows.push([dateStr, ticker.trim().toUpperCase(), price]);

    // Advance to the next day
    currentDate.setDate(currentDate.getDate() + 1);
  }

  // Write all rows at once to Columns A, B, and C
  if (rows.length > 0) {
    sheet.getRange(startRow, 1, rows.length, 3).setValues(rows);
  }
}

```

---

### How to Run / Call This Function

You can execute this function from another script function, a custom menu button, or the Apps Script editor runner:

```javascript
// Example usage:
function runHistoricalImport() {
  // Fetch prices for EXSA.DE from Jan 1, 2024 to Dec 31, 2024, starting at Row 2
  populateHistoricalPrices("EXSA.DE", "2024-01-01", "2024-12-31", 2);
}

```

### Key Improvements

1. **Dynamic Date Range:** Uses a standard `while` loop that increments by 1 day per step, handling month/year transitions smoothly.

2. **Batch Writing (`setValues`):** Instead of updating cells one-by-one, it collects all rows in an array and writes them to Google Sheets in a single bulk operation, minimizing execution time.

3. **Static Output:** The values written to the sheet are plain numbers/text—preventing Google Sheets from ever calling Yahoo Finance again for these historical entries.

I have created an AppScript that I use in a Google Sheet that you find below. This makes a call to the Yahoo Finance API service. However, I would like to avoid having to call this function too many times because Yahoo would apply rate limits. In my spreadsheet I call the function like this

How do I do it?

# ANSWER 05: Gemini Flash

Use `CacheService` in Google Apps Script to store fetched closing prices using 
a unique key made of the ticker and the formatted target date.

The Google Apps Script `CacheService.getScriptCache()` allows you to store values 
for up to 6 hours (21,600 seconds).

---

### Updated Code with Caching

Replace your function with the modified version below:

```javascript
/**
 * Retrieves the closing price for a given ticker symbol on a specific date.
 * Uses CacheService to prevent rate limiting on recurring calls.
 * 
 * @param {string} ticker - Symbol name (e.g., "STOXXIEX.DE", "VOO", "AAPL")
 * @param {string|Date} inputDate - Target date (e.g., "2024-03-15" or a Date cell)
 * @return {number|string} The closing price or an error message.
 * @customfunction
 */
function GET_CLOSE_PRICE(ticker, inputDate) {
  if (!ticker || typeof ticker !== "string") {
    return "Invalid Ticker";
  }

  const targetDate = new Date(inputDate);
  if (isNaN(targetDate.getTime())) {
    return "Invalid Date";
  }

  // Format date boundaries to UTC Unix timestamps (seconds)
  const startOfDay = Math.floor(new Date(Date.UTC(
    targetDate.getUTCFullYear(),
    targetDate.getUTCMonth(),
    targetDate.getUTCDate(), 0, 0, 0
  )).getTime() / 1000);

  const endOfDay = startOfDay + 86400; // Add 24 hours

  // Format date string for cache key (YYYY-MM-DD)
  const formattedDate = targetDate.toISOString().split('T')[0];
  
  // Create a unique cache key: e.g. "EXSA.DE_2026-09-10"
  const cacheKey = `${ticker.trim().toUpperCase()}_${formattedDate}`;
  const cache = CacheService.getScriptCache();
  const cachedValue = cache.get(cacheKey);

  // Return cached result if available
  if (cachedValue !== null) {
    // Return parsed float if cached item is numeric, otherwise return string message
    return isNaN(Number(cachedValue)) ? cachedValue : Number(cachedValue);
  }

  // Encode ticker string for API call (handles symbols like ^GSPC)
  const encodedTicker = encodeURIComponent(ticker.trim());
  const url = `https://query1.finance.yahoo.com/v8/finance/chart/${encodedTicker}?period1=${startOfDay}&period2=${endOfDay}&interval=1d`;

  try {
    const response = UrlFetchApp.fetch(url, { muteHttpExceptions: true });
    
    if (response.getResponseCode() !== 200) {
      return "Ticker not found or API error";
    }

    const json = JSON.parse(response.getContentText());
    const result = json.chart.result;

    if (!result || result.length === 0 || !result[0].indicators.quote[0].close) {
      return "No price found (Market Closed / Weekend)";
    }

    // Extract non-null close prices
    const closePrices = result[0].indicators.quote[0].close;
    const validPrices = closePrices.filter(price => price !== null);

    if (validPrices.length === 0) {
      return "No trading data for this date";
    }

    const price = Math.round(validPrices[0] * 100) / 100;

    // Cache the price for 6 hours (21,600 seconds)
    cache.put(cacheKey, price.toString(), 21600);

    return price;

  } catch (error) {
    return "Error: " + error.toString();
  }
}

```

---

### Key Improvements Made

* **Unique Cache Keys:** Generates keys like `EXSA.DE_2026-09-10` to avoid conflicts between tickers and dates.
* **Maximum Expiration:** Stores values for `21600` seconds (6 hours), the maximum allowed limit for Apps Script cache.
* **String-to-Number Conversion:** Converts the retrieved string value back to a numeric float so Google Sheets treats the output as a number rather than text.

Yes, but you must replace `GOOGLEFINANCE` with a data source that provides 
**historical daily prices**. 

`CACHEFINANCE` is not sufficient for this formula: 

it mainly supplements individual attributes such as current `price`, `name`, 
and `yieldpct`; it does not provide a historical date/close table that can be 
averaged over 200 days. 

[github](https://github.com/demmings/cachefinance)

The cleanest solution is an Apps Script custom function that retrieves 
`Yahoo Finance historical` data for the corresponding Yahoo symbol—for example, 
`EXSA:ETR` → `EXSA.DE` — and returns the 200-day average directly.

## Recommended formula

After installing the script below, use:

```gs
=YAHOO_SMA(E291,200)
```

If `E291` contains:

```text
EXSA:ETR
```

the function converts it to:

```text
EXSA.DE
```

and calculates the average of the available daily closing prices.

You can also use:

```gs
=YAHOO_SMA(E291,200,TODAY())
```

The third argument is optional and is useful when you want a fixed evaluation date.

## Apps Script implementation

In Google Sheets, open **Extensions → Apps Script**, replace the default code, and paste this:

```javascript
/**
 * Calculates the simple moving average of daily closing prices.
 *
 * Examples:
 *   =YAHOO_SMA("EXSA:ETR", 200)
 *   =YAHOO_SMA(E291, 200)
 *   =YAHOO_SMA("EXSA.DE", 200, TODAY())
 *
 * @param {string} symbol Google-style symbol, e.g. EXSA:ETR
 * @param {number} periods Number of trading-day observations
 * @param {Date} asOf Optional end date
 * @return {number}
 * @customfunction
 */
function YAHOO_SMA(symbol, periods, asOf) {
  if (!symbol) {
    throw new Error("Missing symbol.");
  }

  periods = Number(periods || 200);

  if (!Number.isInteger(periods) || periods < 1) {
    throw new Error("Periods must be a positive integer.");
  }

  const yahooSymbol = toYahooSymbol_(String(symbol).trim());

  const endDate = asOf instanceof Date && !isNaN(asOf)
    ? new Date(asOf)
    : new Date();

  endDate.setHours(23, 59, 59, 999);

  // Request substantially more calendar days than trading days.
  const startDate = new Date(endDate);
  startDate.setDate(startDate.getDate() - Math.ceil(periods * 1.7 + 30));

  const period1 = Math.floor(startDate.getTime() / 1000);
  const period2 = Math.floor(endDate.getTime() / 1000);

  const url =
    "https://query1.finance.yahoo.com/v8/finance/chart/" +
    encodeURIComponent(yahooSymbol) +
    "?period1=" + period1 +
    "&period2=" + period2 +
    "&interval=1d&events=history&includeAdjustedClose=true";

  const response = UrlFetchApp.fetch(url, {
    muteHttpExceptions: true,
    headers: {
      "User-Agent": "Mozilla/5.0"
    }
  });

  const status = response.getResponseCode();

  if (status !== 200) {
    throw new Error(
      "Yahoo Finance returned HTTP " + status + " for " + yahooSymbol
    );
  }

  const payload = JSON.parse(response.getContentText());

  if (
    !payload.chart ||
    !payload.chart.result ||
    !payload.chart.result.length
  ) {
    const description =
      payload.chart && payload.chart.error
        ? payload.chart.error.description
        : "No historical data returned.";

    throw new Error(yahooSymbol + ": " + description);
  }

  const result = payload.chart.result[0];
  const timestamps = result.timestamp || [];
  const quote = result.indicators.quote[0];
  const closes = quote.close || [];

  const prices = [];

  for (let i = 0; i < closes.length; i++) {
    const close = Number(closes[i]);

    if (Number.isFinite(close)) {
      prices.push(close);
    }
  }

  if (prices.length === 0) {
    throw new Error("No valid closing prices returned for " + yahooSymbol);
  }

  if (prices.length < periods) {
    throw new Error(
      "Only " + prices.length +
      " daily prices were returned for " + yahooSymbol +
      "; " + periods + " required."
    );
  }

  const recentPrices = prices.slice(-periods);

  return recentPrices.reduce(function(sum, value) {
    return sum + value;
  }, 0) / recentPrices.length;
}


/**
 * Converts common Google-style exchange:ticker symbols to Yahoo symbols.
 *
 * Examples:
 *   EXSA:ETR -> EXSA.DE
 *   ETR:EXSA -> EXSA.DE
 *   LON:VWRL -> VWRL.L
 *   NASDAQ:MSFT -> MSFT
 *   NYSEARCA:SPY -> SPY
 *   EXSA.DE -> EXSA.DE
 */
function toYahooSymbol_(symbol) {
  const upper = symbol.toUpperCase();

  if (upper.indexOf(".") >= 0 && upper.indexOf(":") < 0) {
    return upper;
  }

  const parts = upper.split(":");

  if (parts.length === 1) {
    return parts[0];
  }

  const first = parts[0];
  const second = parts [github](https://github.com/demmings/cachefinance);

  const exchangeMap = {
    "ETR": ".DE",
    "FRA": ".DE",
    "GER": ".DE",
    "MIL": ".MI",
    "BIT": ".MI",
    "LON": ".L",
    "LSE": ".L",
    "AMS": ".AS",
    "EPA": ".PA",
    "PAR": ".PA",
    "SWX": ".SW",
    "TSE": ".TO",
    "TSX": ".TO",
    "ASX": ".AX",
    "HKG": ".HK",
    "TYO": ".T",
    "NASDAQ": "",
    "NYSE": "",
    "NYSEARCA": "",
    "AMEX": ""
  };

  // Google symbols are normally EXCHANGE:TICKER.
  if (exchangeMap.hasOwnProperty(first)) {
    return second + exchangeMap[first];
  }

  // Also support TICKER:EXCHANGE, such as EXSA:ETR.
  if (exchangeMap.hasOwnProperty(second)) {
    return first + exchangeMap[second];
  }

  throw new Error(
    "Unknown exchange in symbol " + symbol +
    ". Use a Yahoo symbol such as EXSA.DE."
  );
}
```

The function uses Yahoo Finance’s chart endpoint, which provides OHLCV historical data 
and daily intervals for symbols supported by Yahoo Finance. Yahoo’s public interface 
is not an official guaranteed API, so it can change or impose access limits; it should 
not be treated as a fully contractual market-data service. 

[quantvps](https://www.quantvps.com/blog/yahoo-finance-api-documentation)

## Important detail: `EXSA:ETR` versus `ETR:EXSA`

Google Finance normally documents the ticker format as:

```text
EXCHANGE:TICKER
```

Therefore, the conventional Google symbol would be:

```text
ETR:EXSA
```

Your cell contains:

```text
EXSA:ETR
```

The script supports both forms, so your existing sheet does not need to be changed. 
For clarity, however, I recommend storing provider symbols explicitly:

| Provider | Symbol |
|---|---|
| Google-style | `ETR:EXSA` |
| Yahoo Finance | `EXSA.DE` |
| ISIN | `DE0002635307` |

The ISIN alone is not enough for the Yahoo endpoint: Yahoo requires a provider-specific ticker.

## Adjusted or unadjusted close

The script currently averages the ordinary `close` field. 
That is the closest equivalent to your original `GOOGLEFINANCE(...,"close",...)` formula.

For ETFs, you may instead want Yahoo’s **adjusted close**, which accounts for distributions. 
That produces a different moving average and is more appropriate for total-return analysis, 
but not necessarily for comparing the SMA with the quoted market price.

To use adjusted closes, replace:

```javascript
const quote = result.indicators.quote[0];
const closes = quote.close || [];
```

with:

```javascript
const quote = result.indicators.quote[0];
const adjusted = result.indicators.adjclose &&
                 result.indicators.adjclose[0];

const closes = adjusted && adjusted.adjclose
  ? adjusted.adjclose
  : (quote.close || []);
```

For a trading signal based on the actual ETF price, keep the unadjusted `close`. 
For a long-term performance analysis, consider adjusted close.

## Why CacheFinance is not the right layer

`CACHEFINANCE` is useful for formulas such as:

```gs
=CACHEFINANCE("ETR:EXSA","price")
```

when you need a current price and Google Finance fails. Its documented fallback attributes 
are primarily `price`, `name`, and `yieldpct`; it caches values and may query third-party 
sources when `GOOGLEFINANCE` returns `#N/A`. 

[github](https://github.com/demmings/cachefinance)

Your calculation requires a time series:

```text
date 1 → close 1
date 2 → close 2
...
date 200 → close 200
```

Consequently, you need either:

- a custom function that retrieves historical data, as above;
- a financial-data API with historical prices;
- a scheduled Apps Script that writes daily prices into a sheet.

Using a current-price fallback 200 times would be slower, less reliable, 
and conceptually incorrect.

## Reliability considerations

Custom functions can be recalculated unexpectedly, and repeatedly calling an 
external endpoint for many ETFs may trigger rate limits. For a small number of 
ETFs, `YAHOO_SMA` is usually convenient. For a larger portfolio, a better architecture 
is to retrieve the daily prices once per day into a sheet and calculate the SMA locally:

```gs
=AVERAGE(FILTER(B2:B1000,A2:A1000>=TODAY()-200))
```

This avoids making one external request every time the spreadsheet recalculates.

Also note that your original formula uses `TODAY()-200`, which represents approximately 200 
calendar days, not 200 trading sessions. The script explicitly returns the last 200 available 
trading-day closes. 

That is normally what “200-day SMA” means.

# ANSWER 01: Perplexity

Yes—but not by changing `GOOGLEFINANCE` itself. 

Google Sheets can query only the securities and attributes available 
in Google Finance’s underlying data feed; it cannot import an ETF 
merely because Google Finance’s website can identify its ISIN. 

Google explicitly notes that some attributes do not work for all 
symbols and that it does not support most international exchanges. 

[support.google](https://support.google.com/docs/answer/3093281)

For this ETF, the issue is probably the **Xetra/ETR quote feed**, 
not the ISIN mapping. `DE0002635307` is correctly associated with 
ticker `EXSA`, and the Xetra listing is also shown as `EXSA` by BlackRock.  

Yahoo Finance, meanwhile, exposes the quote as `EXSA.DE` and currently 
provides delayed Xetra data. 

[blackrock](https://www.blackrock.com/lu/intermediaries/products/251931/ishares-stoxx-europe-600-ucits-etf-de-fund)

## What to try first

Use the exchange-qualified ticker rather than the ISIN:

```gs
=GOOGLEFINANCE("ETR:EXSA","price")
```

You can also test:

```gs
=GOOGLEFINANCE("ETR:EXSA","currency")
=GOOGLEFINANCE("ETR:EXSA","closeyest")
=GOOGLEFINANCE("ETR:EXSA","volume")
```

However, if these return `#N/A`, there is no formula syntax that 
will force Google to retrieve the data. The following alternatives 
are worth testing, but they are not equivalent listings and should 
not be silently substituted in a portfolio:

```gs
=GOOGLEFINANCE("FRA:EXSA","price")
=GOOGLEFINANCE("EXSA","price")
```

`FRA:EXSA` refers to a Frankfurt listing, while `ETR:EXSA` refers to Xetra. 
They may have different liquidity, trading hours, prices, or availability. 
Google recommends specifying both the exchange and ticker to avoid discrepancies. 

[support.google](https://support.google.com/docs/answer/3093281)

## Using Yahoo Finance as the fallback

Yahoo’s symbol is:

```text
EXSA.DE
```

You can sometimes retrieve the current value in Google Sheets with:

```gs
=IMPORTDATA("https://query1.finance.yahoo.com/v8/finance/chart/EXSA.DE?range=1d&interval=1m")
```

But this is not a convenient or stable solution: Yahoo’s response is JSON, 
`IMPORTDATA` may not parse it usefully, and Yahoo can change or restrict 
undocumented endpoints. A better approach is an `Apps Script` function using `UrlFetchApp`, preferably against an official or licensed API.

For example, if an API returns JSON in the form:

```json
{
  "price": 66.04,
  "currency": "EUR",
  "timestamp": "2026-08-19T13:34:01+02:00"
}
```

you could expose a custom Sheets function such as:

```javascript
function YAHOOFINANCE(symbol, attribute) {
  const url =
    'https://query1.finance.yahoo.com/v8/finance/chart/' +
    encodeURIComponent(symbol) +
    '?range=1d&interval=1m';

  const response = UrlFetchApp.fetch(url, {
    muteHttpExceptions: true,
    headers: { 'User-Agent': 'Mozilla/5.0' }
  });

  if (response.getResponseCode() !== 200) {
    throw new Error('Yahoo Finance returned HTTP ' + response.getResponseCode());
  }

  const data = JSON.parse(response.getContentText());
  const result = data.chart.result && data.chart.result[0];

  if (!result || !result.meta) {
    throw new Error('No quote data returned for ' + symbol);
  }

  const meta = result.meta;

  switch (String(attribute).toLowerCase()) {
    case 'price':
      return meta.regularMarketPrice ?? meta.previousClose;
    case 'currency':
      return meta.currency || '';
    case 'previousclose':
      return meta.previousClose ?? '';
    default:
      throw new Error('Unsupported attribute: ' + attribute);
  }
}
```

Then:

```gs
=YAHOOFINANCE("EXSA.DE","price")
```

This should be treated as an example rather than production-grade infrastructure. 
For a reliable portfolio tracker, use a provider with a documented API, 
authentication, rate limits, and terms that permit your intended use.

## Does CacheFinance solve it?

`cachefinance` may help, but it does not extend Google Finance’s database. 
It works as a custom Apps Script function that:

1. Tries `GOOGLEFINANCE`.
2. Uses a cached previous value when Google returns `#N/A`.
3. Attempts third-party websites or APIs for selected attributes such as `price`, `name`, and `yieldpct`.

The project specifically describes unsupported-symbol fallback lookups 
and cached values, but it also warns that third-party lookups can be slow, 
may fail, and may return `0` or an empty value if no source works. 

[github](https://github.com/demmings/cachefinance)

For your ETF, the first test would be:

```gs
=CACHEFINANCE("ETR:EXSA","price")
```

If the library’s Yahoo fallback understands the `ETR:EXSA` format, 
it may convert it to the Yahoo symbol `EXSA.DE`. If it does not, 
try the Yahoo-style symbol:

```gs
=CACHEFINANCE("EXSA.DE","price")
```

Whether that works depends on the version of the script and its source-selection logic. The repository is relatively old—the latest listed release is from November 2022—so I would inspect and test its current Yahoo adapter before relying on it for financial records. 

[github](https://github.com/demmings/cachefinance)

You can also provide a default Google value when Google works intermittently:

```gs
=CACHEFINANCE(
  "ETR:EXSA",
  "price",
  GOOGLEFINANCE("ETR:EXSA","price")
)
```

For an always-unsupported symbol, however, the default itself evaluates to `#N/A`; therefore the third-party lookup must support that symbol format.

## Recommended design

For a portfolio spreadsheet, I would separate **security identity**, **data provider**, and **provider symbol**:

| Security | Exchange | Google symbol | Yahoo symbol |
|---|---|---|---|
| ISIN `DE0002635307` | Xetra | `ETR:EXSA` | `EXSA.DE` |

Then use a fallback formula:

```gs
=IFERROR(
  GOOGLEFINANCE(B2,"price"),
  YAHOOFINANCE(C2,"price")
)
```

Where:

- `B2` contains `ETR:EXSA`.
- `C2` contains `EXSA.DE`.

For a simple personal sheet, `CACHEFINANCE` is worth trying because it gives you caching and fallback behavior with little implementation effort. For a more dependable solution, 
I would use a small Apps Script wrapper around a documented market-data API and store the provider-specific symbol separately from the ISIN.

Do not use cached values for current valuation without also storing the timestamp and source. A cached price can be useful for avoiding gaps in charts, but it should not be mistaken for a current market quote.
